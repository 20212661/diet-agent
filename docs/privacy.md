# 本地数据查看、导出和删除

数据管理命令只作用于当前 `USER_ID`：

- `/data` 显示数据库记录、会话文件、导出文件、请求日志和全局迁移备份数量。
- `/diet-export` 生成 JSON 导出，包含画像、厨房和库存、餐食、反馈、饮食计划、周计划、Web 写入去重记录、聊天请求状态与最终回复，以及当前用户的 Pi 会话和请求日志文件。Pi 自带的 `/export` 单独导出 Pi 会话。
- `/delete-data` 显示删除预览；再次输入 `/delete-data CONFIRM` 并在 Pi 确认框中确认后执行。应用会在安全关闭 Pi 后删除数据；下次启动时会创建空白会话。

删除会清空当前 SQLite 数据库中的用户记录、饮食计划及幂等操作记录（含 Web 写入请求与响应、聊天请求状态与最终回复）、当前用户的持久会话、JSON 导出和请求日志；同时会从现存迁移备份副本中删除该用户的数据库记录。若某份备份无法读写，命令会报告未清理份数，用户数据删除结果不能视为完整。

迁移备份与数据库保存在相同目录；最多留存最近 3 份，单份最长 30 天。程序启动时会执行过期清理。手工复制的数据库、导出文件、系统快照、云盘同步或外部备份不受本地删除命令管理，需由维护者另行删除。

模型 API 请求诊断日志默认关闭。显式设置 `ENABLE_REQUEST_LOGGING=1` 会保存完整请求消息和模型响应，可能包含饮食、过敏或健康信息；本地 `/data` 会显示当前用户日志文件数，`/delete-data` 会删除其日志目录。Agent 普通控制台诊断日志只输出用户 ID 哈希、工具名称和操作状态，不记录工具参数/结果内容或模型错误正文。

## 目录位置

- SQLite 数据库、会话与导出：项目 `data/`；可用 `DIET_AGENT_DB_PATH` 指定数据库文件位置。
- API 请求日志：项目 `logs/api-requests/<user-hash>/`。
- 迁移备份：数据库文件旁，文件名带 `.bak`。
