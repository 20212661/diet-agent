# 第 1 阶段：家庭多人模式实现计划

## Context

现状是单账号单人模型：`UserProfile`（`src/types/diet.ts:21-36`）承载过敏/忌口/口味，全库按 `user_id` 字符串分区，无成员概念。目标是让一个账号下管理多个家庭成员（各带过敏/忌口/口味），排菜时按"今晚谁吃"做并集硬过滤 + 成员等权口味加权，同时守住既有安全红线（**过敏忌口只存画像、绝不进任务状态**；dismissed 警告重提示不排除候选——已确认）。

已确认的三个决策：**主账号"我"建模为虚拟成员**（从 UserProfile 投影，成员表只存其他成员，零回填无双源）；**口味成员等权**（人均命中分，单人行为不变）；**重提示只展示不排除**。

## 核心设计

**运行时统一投影** `DiningMember`（新文件 `src/services/household.ts`）：

```ts
interface DiningMember { memberId: string /* "self" 或物理 ID */; name: string; isSelf: boolean;
  allergies: string[]; avoidFoods: string[]; preferences: string[] }
```

- `resolveDiningMembers(userId, refs?: string[])`：refs 为空 = `[self, ...全部物理成员]`（默认全吃）；refs 接受成员 ID 或精确名（"我"/"self" 映射虚拟成员），解析不到抛错。成员上限 8。
- `composeDiningSafetyProfile(members): FoodSafetyProfile`：allergies/avoidFoods 取并集——`assessFoodSafety`（`src/recipes/foodSafety.ts:40`）只吃这两字段，天然可合成，全部硬过滤路径不改判定逻辑。
- 单人存量数据：`meal_plans`/`weekly_plans`/`task_states` 新列 NULL = `["self"]`，行为与旧版完全一致。

### PR C — 排菜多人化（核心）

1. `TaskState`（`src/tasks/taskStateTypes.ts`）加 `diningMembers?: string[]`（memberId 数组，**只存 ID 不存过敏内容**，红线注释同步更新）；`taskStateService.noteMealPlanToolCall` 的 outcome 加 diningMembers 确定性写入；`taskStateRepository.updateTaskState` 白名单加字段；`buildTaskStateInjection` 显示"用餐成员：我、小明"（仅名字）。语义提取器 `sanitizePatch` **不加**此字段（保持代码独占写入）。
2. 排菜工具（`generateMealPlan.ts` / `generateWeeklyPlan` / `generateCookingPlan` / `searchRecipes.ts`）：Params 加 `diningMembers?: string[]`（成员名或 ID），promptGuidelines 注明"先 get_household_members 确认，用户说某人不吃时传入；不传默认全部"。
3. 过滤接线：`mealPlanBuilder.ts` L172-176 合成 userProfile 处改为并集（goal 等仍用"我"的画像，allergies/avoidFoods 替换为 `composeDiningSafetyProfile` 并集 + temporaryAvoidFoods）；`weeklyPlanService.ts`、`generateCookingPlan.ts`、`searchRecipes.ts` 同样；保存计划时写 `dining_members_json`。
4. 重校验：`mealPlanValidation.ts` `revalidateMealPlan` 按计划保存的 dining_members 重放成员集合（旧计划 NULL=仅"我"，行为不变）；每周计划换菜（`weeklyPlan.ts` 的 alternatives/replace）用计划保存的成员集。
5. 口味加权（`src/recipes/recipeMatcher.ts` L323-330）：`MatchRecipeInput` 加 `diningMembers?: DiningMember[]`；有成员且任一有 preferences 时，每成员命中 `recipe.tasteTags` 得 `4 * hits / memberCount`（reasons 注明"符合小明口味"）；成员均无 preferences 或未传 → 回退现行 `kitchenProfile.tastePreferences` +4（**单测断言单人输出与旧版一致**）；cookingPreferences/desiredStyle 保持厨房级不动。

### PR D — dismissedAllergenWarnings 跨成员重提示

1. `src/import/userRecipe/saveRecipe.ts` `buildDismissedAllergenWarnings` 写入 `dismissedByMemberId: "self"`（web 导入操作者恒为"我"）。

## 不在第 1 阶段范围

- 记餐/营养计算不按成员拆分（仍按"我"）；成员无独立健康画像（身高/体重/目标）。
- 周计划整期一个成员集（按天不同成员走"今晚重排"chat 路径）。
- 无成员级认证/登录（单账号内数据）。
