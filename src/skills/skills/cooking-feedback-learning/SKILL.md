# 做饭反馈沉淀 Skill

## 适用场景

当用户评价一次做饭方案、菜谱、口味、耗时、洗碗量或是否下次推荐时使用。

典型表达：

- 今天这个菜不错
- 太咸了
- 太淡了
- 太辣了
- 这个太麻烦
- 这个适合工作日
- 下次别推荐这个
- 下次还可以吃
- 洗碗太多
- 油烟太大
- 主动操作太久
- 这个菜我给 4 分

## 目标

把用户对菜谱和做饭流程的反馈结构化记录下来，帮助后续推荐越来越贴合用户。

## 工具调用流程

调用 log_cooking_feedback。

应尽量提取以下维度：

- 菜名或方案名
- 口味评价
- 评分
- 主动操作时间
- 总耗时
- 体力负担
- 洗碗负担
- 油烟负担
- 是否适合工作日
- 是否下次推荐
- 需要调整的调味
- 用户明确负反馈

## 反馈解释规则

1. 评分高不等于总是推荐。
2. 如果口味评分高但体力负担高：
   - 工作日晚饭默认降权。
   - 用户说累时不要推荐。
   - 周末或用户有精力时可以推荐。
3. 如果用户说"下次别推荐"，应明显降权。
4. 如果用户说"适合工作日"，工作日晚饭可优先推荐。
5. 如果用户说"太咸 / 太辣 / 太淡"，下次方案应调整调味。
6. 如果用户说"洗碗太多"，下次优先一锅出或烤箱托管。
7. 如果用户说"太麻烦"，下次减少步骤、减少并行任务。

## 回复规则

工具成功后，简短确认：

- "已记录：这道菜口味不错，但工作日负担偏高。"
- "已记录：下次会降低咸度，并优先给少洗碗版本。"

不要在工具失败时说已记录。
