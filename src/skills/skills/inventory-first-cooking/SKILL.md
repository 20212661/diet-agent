# 库存优先做饭规划 Skill

## 适用场景

当用户表达以下需求时使用：

- 今晚吃什么
- 冰箱里有什么能做
- 用掉某个食材
- 快过期食材优先
- 不想买菜
- 根据现有库存做饭
- 帮我清库存

## 目标

优先使用已有食材和快过期食材，为用户生成合适的晚饭方案。

## 工具调用流程

### 第一步：查询库存

调用 get_ingredient_inventory。

重点关注：

- available 食材
- expiring_soon 食材
- 购物清单
- 数量未知的食材
- 位置未知的食材

### 第二步：必要时查询厨房条件

如果方案需要厨具安排，而当前上下文没有厨房条件：
调用 get_kitchen_profile。

### 第三步：搜索候选菜谱

如果用户只是想看几个选择：
调用 search_recipes。

如果用户需要完整步骤：
可以先调用 search_recipes，再调用 generate_cooking_plan。

### 第四步：生成完整方案

如果用户要求完整晚饭安排：
调用 generate_cooking_plan。

## 库存解释规则

1. available 食材可以作为已有食材使用。
2. expiring_soon 食材应优先考虑。
3. shopping_list 只能说成需要购买，不能说成已有。
4. 数量未知时不要编造数量。
5. 位置未知时不要编造冷藏、冷冻或常温。
6. 不要编造保质期。
7. 不要把"建议购买"说成"已经购买"。

## 输出要求

如果生成完整方案，必须区分：

- 已有食材
- 快过期优先处理食材
- 需购买食材
- 已避开食材

## 禁止事项

- 不要在没有库存工具结果时声称"冰箱里有……"
- 不要把购物清单当库存。
- 不要为了凑菜谱编造食材。
